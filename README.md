# VPNBot

Telegram-бот для выдачи VPN-доступа через WireGuard/AmneziaWG. Проект реализован на `aiogram`, хранит пользователей, подписки, устройства и трафик в PostgreSQL, поддерживает тарифы, пробный период, реферальные бонусы и базовую админ-панель.

> Текущий статус: проект выглядит как MVP/прототип. Генерация VPN-профиля в `vpn/wireguard.py` возвращает шаблонный WireGuard-конфиг, а оплата в обработчике подписки пока помечена как mock. Для продакшена нужно подключить реальный VPN-backend, безопасную генерацию ключей и полноценную платёжную обработку.

## Возможности

- `/start` с автоопределением языка пользователя и выдачей пробного периода на 7 дней.
- Главное меню со статусом подписки, текущим тарифом и количеством подключённых устройств.
- Генерация `.conf`-файла и QR-кода для подключения VPN-профиля.
- Лимиты устройств по тарифам: пробный период, тариф на 2 устройства и тариф на 5 устройств.
- Раздел «Мои устройства» с повторной отправкой сохранённых конфигов.
- Реферальная система: пользователь получает +7 дней за друга, который пришёл по ссылке.
- Мультиязычные тексты: русский и английский с fallback на английский.
- PostgreSQL-хранилище для пользователей, подписок, устройств и дневного трафика.
- Админ-панель: статистика, трафик, системная информация, рассылки, подарочные часы, бан/разбан.
- FastAPI webhook-заготовка для приёма уведомлений об оплатах.

## Стек

- Python 3.10+
- aiogram 3
- PostgreSQL 14+
- psycopg 3 / psycopg-pool
- FastAPI для webhook-эндпоинта

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone <repo-url>
cd vpnbot-main
```

### 2. Создать виртуальное окружение

```bash
python -m venv .venv
source .venv/bin/activate      # Linux/macOS
# .venv\Scripts\activate     # Windows
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

В коде также используются пакеты, которых может не быть в текущем `requirements.txt`:

```bash
pip install python-dotenv "qrcode[pil]" fastapi uvicorn
```

Рекомендуется добавить их в `requirements.txt`, чтобы новый запуск проекта был воспроизводимым.

### 4. Поднять PostgreSQL

Пример через Docker:

```bash
docker run --name vpnbot-postgres \
  -e POSTGRES_DB=vpnbot \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=admin \
  -p 5432:5432 \
  -d postgres:14
```

Бот сам вызывает `init_schema()` при запуске и создаёт необходимые таблицы, если их ещё нет. Альтернативно схему можно применить вручную:

```bash
psql "postgresql://postgres:admin@localhost:5432/vpnbot" -f schema_pg.sql
```

### 5. Настроить переменные окружения

Создайте `.env` в корне проекта:

```env
BOT_TOKEN=telegram_bot_token_here
PROVIDER_TOKEN=telegram_payment_provider_token_here
WEBHOOK_URL=https://example.com/yookassa
ADMIN_IDS=123456789,987654321
POSTGRES_DSN=postgresql://postgres:admin@localhost:5432/vpnbot
```

Описание переменных:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather. |
| `PROVIDER_TOKEN` | Токен платёжного провайдера Telegram. Сейчас почти не используется, потому что оплата mock. |
| `WEBHOOK_URL` | URL webhook-обработчика платежей. |
| `ADMIN_IDS` | Список Telegram ID администраторов через запятую. |
| `POSTGRES_DSN` | DSN подключения к PostgreSQL. |

> Не коммитьте реальный `.env` в Git. Для публичного репозитория лучше хранить только `.env.example` без секретов.

### 6. Запустить бота

```bash
python bot.py
```

При старте бот:

1. открывает пул соединений PostgreSQL;
2. создаёт таблицы и индексы, если они отсутствуют;
3. проверяет соединение через `SELECT 1`;
4. запускает long polling.

## Запуск webhook-сервера

Webhook-заготовка находится в `webhook.py` и принимает POST-запросы на `/yookassa`.

```bash
uvicorn webhook:app --host 0.0.0.0 --port 8000
```

Сейчас обработчик сохраняет payload платежа в `payments.json`. Для боевого режима нужно добавить проверку подписи/источника webhook, обработку статусов платежа и обновление подписки пользователя в PostgreSQL.

## Пользовательские сценарии

### Старт и главное меню

- Пользователь отправляет `/start`.
- Бот сохраняет пользователя в PostgreSQL.
- Новому пользователю выдаётся trial на 7 дней.
- Если `/start` содержит payload с Telegram ID реферера, бот начисляет рефереру +7 дней.
- Главное меню показывает тариф, лимит устройств, подключённые устройства и остаток подписки.

### Подключение устройства

1. Пользователь открывает «Устройства».
2. Выбирает «Телефон» или «Компьютер».
3. Бот проверяет лимит устройств по тарифу.
4. Генерирует VPN-конфиг.
5. Отправляет `.conf`-файл и QR-код.
6. Сохраняет конфиг в таблицу `devices`.

### Подписка

В разделе подписки доступны планы:

| План | Лимит устройств | Доступные сроки |
|---|---:|---|
| 2 устройства | 2 | 1, 3, 6 месяцев |
| 5 устройств | 5 | 1, 3, 6 месяцев |

Сейчас создание платежа реализовано как mock-сценарий: бот показывает сообщение «Оплата создана (мок)» и логирует выбранный тариф.

## Админ-команды

Доступны только пользователям, чьи Telegram ID указаны в `ADMIN_IDS`.

| Команда | Назначение |
|---|---|
| `/admin_panel` | Открыть inline-админ-панель. |
| `/stats` | Показать количество пользователей, активные подписки, разбивку по тарифам и churn за 7 дней. |
| `/traffic` | Показать суммарный трафик за 1, 7 или 30 дней. |
| `/sysinfo` | CPU, RAM, диск и uptime процесса. |
| `/about` | Версия, тарифы и лимиты из `settings.py`. |
| `/send_to_one <user_id> <text>` | Отправить сообщение одному пользователю. |
| `/send_to_all <text>` | Рассылка всем пользователям. |
| `/gift_to_one <user_id> <hours>` | Начислить часы одному пользователю. |
| `/gift_to_all <hours>` | Начислить часы всем пользователям. |
| `/config <user_id>` | Вывести сохранённые устройства и config ID пользователя. |
| `/ban <user_id>` | Заблокировать пользователя. |
| `/unban <user_id>` | Разблокировать пользователя. |

## База данных

Проект использует PostgreSQL и следующие таблицы:

- `users` — Telegram-пользователи, локаль, ban status, реферальные данные.
- `subscriptions` — тариф, статус, дата старта и окончания подписки.
- `devices` — подключённые устройства, config ID, статус, трафик, handshake.
- `traffic_daily` — дневная агрегация upload/download трафика.

Все запросы идут через helpers в `db.py`:

- `fetchone()`
- `fetchall()`
- `execute()`
- `executemany()`
- `ping()`

## Что важно доработать перед продакшеном

- Заменить шаблонный WireGuard-конфиг на реальную генерацию ключей и peer-конфигураций.
- Убрать hardcoded приватный ключ и endpoint из `vpn/wireguard.py`.
- Добавить полноценную интеграцию платежей: создание invoice/payment, webhook verification, продление подписки после успешной оплаты.
- Перенести все секреты в `.env`/secret manager и удалить `.env` из репозитория.
- Расширить `.gitignore`: `.env`, `.venv/`, `payments.json`, runtime-файлы, логи.
- Добавить миграции, например Alembic, вместо ручного SQL/автосоздания схемы в коде.
- Добавить тесты для storage, тарифов, рефералов и лимитов устройств.
- Настроить линтеры и форматтеры: `ruff`, `black`, `mypy` по желанию.
- Добавить Dockerfile и `docker-compose.yml` для бота и PostgreSQL.

## Безопасность

Перед публикацией репозитория проверьте, что в Git не попали:

- `.env` с токенами;
- реальные Telegram/payment токены;
- приватные WireGuard-ключи;
- production DSN базы данных;
- `payments.json` с платёжными payload;
- пользовательские данные из `users.json` или базы.

Минимальный `.gitignore` для проекта:

```gitignore
.env
.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.ruff_cache/
.mypy_cache/
*.log
payments.json
users.json
```
